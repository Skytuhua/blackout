## Integration contract and reproduction

Import `startInteraction`, `continueInteraction`, `executeToolIntent`, and `renderFacts` from `src/llm/client.ts`. Import `ScopedContext` from `src/llm/tools.ts`.

1. Assemble the frozen `GatewayStart` from the actor's `SimulationClient.observe(actorId)` projection and only that view's permitted procedure texts. Use role matching that actor; player may use role `debrief` with engine-supplied `debriefContext`.
2. Keep an AbortController for each interaction. Call `startInteraction(input, signal)`.
3. On a `tool_request`, execute `executeToolIntent(reply.intent, { start: input, simulation: client, signal })`. Retain that same context object for exact duplicate calls; stable hashed engine keys also protect repeated dispatch across context objects. No simulation dependency means inspection explicitly rejects with `inspection_worker_required`.
4. Observe a fresh actor view and send the frozen `GatewayContinue` with matching interaction/call/run/request/actor IDs and the scoped result. End normally when the provider acknowledges a dispatched task; a later terminal task event starts a separate bounded interaction.
5. UI must render numeric/state facts from `renderFacts`/permitted records. Label `inference` and `uncertainty` explicitly. Proposed actions still use ordinary player confirmation and command validation.
6. On reset, abort all old interaction controllers and create a new run ID. Cancel/reset HTTP routes accept only `GatewayStartSchema.pick({runId:true,requestId:true,actorId:true})`; they cancel that originating identity. They do not mutate simulation state.

Read tools use the supplied scoped view/procedures. Inspection requires a known asset, an allowed inspect affordance, an eligible explicitly selected technician, and the observed target version. Site-level workload proposals are accepted only through a granted affordance. Missing action versions fail closed. Tools never read snapshots or engine internals. The gateway cannot independently authenticate browser-generated observations; the trusted engine/client projection remains the source boundary specified by the plan.

Offline/mock reproduction: `npm run test:llm`. Scripted production reproduction: `npm run build`, set `LLM_MODE=scripted`, then `npm run demo`; GET `/api/health` is nonbillable, and POST a frozen start envelope to `/api/llm/turn` returns labeled scripted fallback without SDK construction. The authored fallback leaves engine actions available.

## Accounting and limits

- Default model `gpt-5.6-luna`, official endpoint only, `reasoning.effort=none`, `store=false`, `maxRetries=0`, `parallel_tool_calls=false`.
- One active provider operation in the production gateway. Cancellation releases the client request immediately but retains the provider slot until transport settles. Late output cannot dispatch tools; known late usage is still reconciled.
- Three calls per coworker interaction, including tool rounds; tools disabled on call three. One debrief call. 24 reserved provider invocations per mission, persisted across restart. New run IDs cannot replenish the separate default $5 local allowance.
- 400 coworker / 800 debrief output tokens; 8s coworker call / 18s coworker interaction / 20s debrief deadlines.
- Planned input cap is 6,000 tokens using `ceil(serialized UTF-8 request bytes / 2)`, including instructions, schemas and retained history. This is a planning estimate, not the model tokenizer. AI-02 must measure/calibrate actual representative input usage; oversize requests fail before transport. Each call reserves the entire 6,000-token planned ceiling and maximum output cost.
- Input reservations and local debits use the conservative $0.25/M cache-write ceiling (ordinary input nominally $0.20/M), output $1.20/M, without cached-input discounts. Known usage reconciles token counts; missing/ambiguous usage retains the maximum reservation. Local debits are conservative allowance accounting, not a provider invoice.
- JSON bodies bounded to 64 KiB; 60 local API POST requests/minute; exact loopback Host/Origin checks; 22s HTTP deadline. SDK and gateway errors do not expose raw provider errors or secrets.
- Up to 128 retained interaction entries per process; reaching the bound yields labeled fallback. Diagnostics retain at most 64 metadata entries, with returned model ID, identity, usage, duration and status, and no raw prompts/output.
- Existing atomic ledger writes assume the single local gateway process that owns port 4173; no cross-process distributed ledger locking.
