## Implementation and contract assumptions

`OperationalView` consumes only `KnowledgeView`. Selection invokes `onInspect(assetId)`; dispatch emits the frozen `ActionIntent` through `onAction`; coworker messages invoke `onAskCoworker`. Affordances control action eligibility and technician choices; travel and work seconds are rendered from the affordance. An empty batch-ceiling field cannot become a zero-percent action. Engine validation and command receipts remain the host's responsibility. Public tasks drive displayed crew status and progress. Observations include observed and received times and quality; readings older than 10 simulation seconds are labeled stale using the mission verification window, not a claim about sensor accuracy. Unknown, future-dated, or unrecognized state never lights an active indicator. Observed readings are listed rather than inventing interpolated trends. Summary values use their single shared `observedAt` timestamp.

The four authored PNG masters are generated by `node src/game/generate-assets.mjs`; dimensions, frames, 24-color palette, anchors, footprints, provenance, and static animation status are in `public/assets/atlas.json`. Grid and sprites use Phaser 4 namespace imports, a 320x192 canvas, integer logical placement and integer CSS scales. Indicators and overlay outlines are separate, derived from observations; no covert fault is drawn. Work is static, with no independent decorative animation.

## Integration blockers and limits

- Frozen props do not expose pause/speed state or controls, retry, command receipts, or a run-level reset callback. Smallest proposed addition: `playback: { paused: true, speed: 1 }`, `onPlaybackChange({ paused: false, speed: 1 })`, and `onRetry()`. Affected consumers: coordinator host/worker bridge and `OperationalView`; receipt/error UI also needs a scoped receipt prop or host feedback. No interface change was made here.
- The current UI does not provide a result retry control, a collapsible mobile inspector drawer, or full charted historical trends. Mission result text is shown only when projected status says success/failure. It does not establish G1, mission completion, live provider behavior, laptop/DPR acceptance, or release readiness.
- Only static master frames exist: no directional technician/walk frames, cooling fan frames, interpolation, or simulation-time-linked animation. None are claimed as complete. Separate static symbols are used for power cabinets.
- DOM controls and equipment list have 44px targets. Phaser asset zones are at least 16 logical pixels, which are 48 CSS pixels at 3x but smaller at 1x/2x. Mobile selection remains available via the accessible list; mobile canvas hit areas need an explicit non-overlapping touch design before claiming the 44px requirement for the map.
- Fixture observations provide few field names; the map's conservative state indicator recognizes only `state`/`power` values documented in the implementation, and overlay outlines look for observed temperature/power fields. Coordinate real engine field names with the simulation owner. Unknown values remain unknown.
- The preview tab could not be closed: the available preview tool surface had no close operation, and Ctrl+W did not close it. It is an agent-owned background tab; no other user's tab was touched.
