## Root integration proposal and exact API example

Root routing, loading saved runs, replay clock/worker coordination, comparison execution, asynchronous generation guards, provider/fallback behavior and host persisted-record v2 remain coordinator-owned. No hotspot edits were needed to compile or exercise this component. Proposed root-only wiring:

```tsx
import { DebriefView, type DebriefViewProps } from './ui/debrief/DebriefView';
import type {
  OutcomeLedger, ComparisonResult, PublicMessage, AgentResponse, GatewayStart,
} from './shared/contracts';

// These values/functions are owned by the host route, not by DebriefView.
// ledger: OutcomeLedger; comparison: ComparisonResult | null;
// recordedDialogue: PublicMessage[];
// explanationResponse: AgentResponse | null;
// explanationStart: GatewayStart | null; // matching start used for that response
const debriefProps: DebriefViewProps = {
  ledger,
  comparison,
  dialogue: recordedDialogue,
  // Produce this projection at the host's recorder boundary. Pass no RunRecord.
  capOptions: recordedCommands
    .filter(c => ['accepted', 'applied'].includes(c.receipt.status)
      && ['pause_batch', 'set_batch_ceiling'].includes(c.intent.action))
    .map(c => ({
      sequence: c.sequence, at: c.at,
      label: `${c.intent.action} · ${c.intent.targetId}`,
    })),
  replay: { cursor: replayTime, playing: replayPlaying },
  onSeek: seekRecordedRun,
  onToggle: toggleRecordedPlayback,
  onCompare: ({ sequence, earlierAt }) => requestEarlierCapComparison({
    commandSequence: sequence, earlierAt,
    // requestEarlierCapComparison owns unique branchRunId and library/worker use.
  }),
  comparisonBusy,
  comparisonError,
  onRetry: startFreshMission,
  onReturn: returnToRecordedRun,
  explanation: explanationResponse && explanationStart
    ? { response: explanationResponse, context: explanationStart } : null,
  explanationBusy,
  explanationError,
  onRequestExplanation: requestBoundedDebriefExplanation,
};
return <DebriefView key={ledger.runId} {...debriefProps} />;
```

`ledger`, `comparison`, `dialogue`, `capOptions`, `replay` and the six callbacks are required. Busy/error/explanation properties are optional; `comparison` explicitly accepts null. `capOptions` is only a UI projection of existing accepted pause/ceiling commands (sequence, original simulation seconds, display label), not a second action schema.

Callback contract:

- `onSeek(at: number)`: range or recorded-event button requests simulation seconds. Root supplies the resulting cursor; the component does not advance an engine or invent replay state. Full recorded event/conversation archives retain their timestamps rather than pretending future archive entries are current observations.
- `onToggle()`: requests play/pause; label reflects provided `replay.playing`. No timer is installed by the component.
- `onCompare({ sequence, earlierAt })`: explicit form submission only. Empty, negative, fractional, same/later time and busy submissions cannot invoke it. `earlierAt` is a whole second, nonnegative and strictly before the selected original `at`. Root must revalidate sequence eligibility, create a unique branch ID and own CPU/worker execution. Busy disables the form; an error is visible beside the form and the same action retries it.
- `onRequestExplanation()`: explicit button only, never mount/render/replay/seek. Root creates the bounded debrief GatewayStart, retains its request identity, invokes the existing gateway and supplies the matching response/context. Keep proposals empty for this read-only explanation. Null is an authored help state; busy disables repeated requests; errors are labeled and can be retried explicitly.
- `onRetry()`: explicit fresh-mission request. `onReturn()`: explicit return to the host's recorded-run route. Root owns navigation and focus on route changes. No hidden transition occurs in the component.

Frozen shared v1 inputs are reused directly. There is no Checkpoint, RunRecord, TruthState, gateway transport, dispatch or persistence prop/import. Host record v2 does not require changing this API. Root already loads Barlow Condensed and IBM Plex Sans; the component adds no fonts/assets/dependencies.

## Accounting and fact boundaries

- Original run summary uses only its engine ledger, prominently labeled `Original run, simulation truth` with `ledger.horizon`. Mission success/failure and terminal time come from a terminal timeline event if present. No terminal event means no terminal status/time is invented. Continued physical accounting is explained separately.
- Complete comparison uses provided baseline/alternative at the supported equal horizon. The policy string is rendered directly from `comparison.continuationPolicy`. Delivered/demand work, batch completion/arrivals/backlog/delay and peak temperature all remain actual supplied metrics.
- Unsupported comparison uses **only** `validPrefix.baseline` and `validPrefix.alternative` for its table and all three charts/sample tables. The first invalid retained action, target, sequence, recorded time, reason and supported horizon are visible. Full-horizon alternative claims are withheld. Original full-run summary is a separately labeled section, never a column paired against the prefix.
- The test deliberately places the original **100 s** ledger in unsupported top-level `baseline`, while both prefix ledgers are **10 s**. That permitted schema shape catches accidental full-baseline fallback. Comparison output is withheld if selected ledger horizons disagree with `supportedHorizon`.
- Grounded explanation parses the shared AgentResponse schema and validates GatewayStart and matching run/request/actor/speaker/debrief context. Stale comparison identity/horizon, stale fact values, unknown/invalid selectors and action proposals withhold the explanation. `factValue` and `renderFacts` resolve selectors against current inputs. During unsupported comparison this means prefix ledgers, never the original full ledger. Observation facts retain observed/received times and units. Inference, uncertainty and response mode are separately labeled; model prose does not supply metric values or HTML.
- Temperature/service/backlog geometry uses telemetry only. Axis units, baseline/earlier-cap legend and action markers are labeled. DOM table contains exact samples. Empty telemetry produces an explicit state and no inferred trend. Units are fictional game compute units; thermal truth is identified as a modeled inlet proxy, distinct from observed evidence.
- Recorded PublicMessages preserve original `live`/`scripted`/`recorded`/`system` modes under `Recorded conversation`. Text is React-escaped. The fixture appends two explicitly authored conversation lines to exercise live/scripted labeling and HTML escaping; physical metrics remain library-generated.
